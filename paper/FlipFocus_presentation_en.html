FlipFocus

A Browser-Based Multi-Sensor Fusion Tool for Phone Flip Detection and Analysis

Reducing the cost of mobile HCI experimentation from "build an app" to "share a link"

Decheng Wang  |  Shanghai Sanlin High School  |  CHCI 2026

Motivation

Many people habitually flip their phone face-down before working or studying —
does this two-second action carry the weight of declaring "focus mode engaged"?

But studying this faces a

fundamental tool barrier

✗ Deployment Barrier

Native app per study, store review, user install — weeks of overhead

✗ No Specialized Tool

Existing EMA platforms do surveys, not phone-state sensing

✗ Sensor Homogeneity Assumption

iOS Safari lacks AmbientLightSensor; Huawei blocks proximity — fixed-stack tools fail

Core Design Philosophy

Adaptive three-tier sensor degradation —
transforming cross-device heterogeneity from a flaw into a feature

Three Core Modules

Module A: Degradation Engine

Runtime probing of accelerometer, light, and proximity sensors

→ Auto-select fusion mode

→ Missing sensor → no experiment failure

Real-time quality indicator in UI

Module B: State Machine

3-second confirmation window

±5 s transition-period exclusion

XY stationarity check (σ² < 0.1g)

F1 = 0.970 dual-sensor mode

Module C: Experiment Ecosystem

Four-condition within-subjects paradigm

Standardized materials + questionnaire

Python analysis pipeline

Link → data → figures: complete workflow

Real-World Feasibility Deployment

4 participants × 25 min × 4 conditions | First complete sensor recordings

Finding 1: P1 (Active Flip) — 4 clean flip cycles, 452 s face-down total
→ State machine correctly captures all events; 3 s window filters noise

Finding 2: P2 (Face-Up Control) — 6 spontaneous flips, 265 s total
→ Told to keep phone face-up, yet could not resist — habituality evidence

Finding 3: 4.9 s ultra-short face-down interval
→ Immediate self-correction — instruction partially observed but insufficient
